# Preview-art style guide: "Quiet Structure"

Publication previews for awni.xyz. Each image is an abstract, algorithmic
rendering of one key idea from a paper. It is not a figure from the paper.

## Philosophy

Quiet Structure treats a paper's central idea as a mechanism that can run.
Paths are sampled, relations are computed, version spaces are cut, and the
picture is what that process leaves behind. Every image is generated by a
small, seeded algorithm whose parameters mean something in the paper's own
terms (number of hypotheses, attention scores, layers, agents). A reader of the
paper should recognise the mechanism; anyone else should see a calm, balanced
abstract diagram.

The vocabulary is deliberately small: dots, lines, arcs, rounded cells. It uses
flat ink on a quiet tile, with one accent colour that marks *the* idea: the
trace, the relation, the surviving hypothesis. Everything else recedes into
greys and faint scaffolding. Restraint is the point. The images must sit
together in a list of eleven and read as one series.

Craft shows in the tuning: stroke weights chosen so the structure survives a
96×72 thumbnail, crossings knocked out cleanly with background halos, density
that turns into texture rather than noise, and compositions that fill the frame
with one confident silhouette. Each sketch should look like it was refined over
many iterations by someone at the top of the field of generative diagramming.

## Canvas and output

- Canvas: **1200×900 (4:3)**, `pixelDensity(1)`. Draw in these coordinates.
- Output: PNG via the shared harness (below). It is later exported as WebP of 200 KB or less.
- The same source must render correctly under **any** palette (light or dark).
  Never hard-code a colour or assume a light background.

## Palette: six tokens, nothing else

The harness derives the tokens from a site theme's `bg`, `fg` and `accent`,
so every image can be re-rendered when the site theme is chosen.

| token        | role                                                       |
|--------------|------------------------------------------------------------|
| `C.bg`       | tile background (already filled before `draw` runs); also the knockout/halo colour |
| `C.ink`      | primary structure: the main nodes and lines                |
| `C.ink2`     | secondary structure: supporting lines, less important nodes |
| `C.faint`    | scaffolding and texture: grids, lattices, rejected alternatives |
| `C.accent`   | **the one key idea.** One element or one family only      |
| `C.accentSoft` | a fill or halo behind the accent element (e.g. a region)   |

Helpers: `C.alpha("ink2", 0.4)` gives an rgba string (for overlap density);
`C.mix("ink", "bg", 0.3)` gives an intermediate tone. `C.dark` is a boolean, but
avoid branching on it.

Accent budget: at most about 12% of the canvas area, and usually much less. If
everything is accent, nothing is.

## Strokes and shapes (at 1200×900; ×0.08 ≈ thumbnail px)

| weight      | use                                        | at 96×72 |
|-------------|--------------------------------------------|----------|
| 16–20 px    | hero line (usually accent)                 | ~1.5 px  |
| 10–12 px    | primary ink lines, ring outlines           | ~1 px    |
| 6–8 px      | secondary lines (`ink2`)                    | sub-pixel, reads as tone |
| 4–5 px      | texture (`faint`), many-line families      | texture  |

- Primary nodes are 70–130 px in diameter; secondary nodes 30–50 px; lattice dots 7–12 px.
- Shapes: filled discs, rings, straight segments, smooth curves (sampled
  polylines or arcs), rounded rectangles (corner radius 4–26 px). Round caps
  and joins (the harness sets these).
- **Knockout halos:** where an important element sits on lines, draw a `C.bg`
  disc or stroke about 20–26 px larger first, so crossings read cleanly.
- Not allowed: free text or words (beyond the sparse labels below), arrowheads,
  gradients, shadows, glows, blur, paper grain or noise textures (they also
  bloat the file), photographic or 3D effects, and anything copied from the
  paper's figures. Paper figures may inspire the structure, but the result must
  be re-drawn abstractly in this vocabulary.

## Labels and marks (round 2)

Round-1 images were often too abstract: you couldn't tell what each element
stood for. Light math labels and marks are now allowed to ground the picture.

- Use **only the harness helpers**, so every tile shares one typographic voice:
  - `label(str, x, y, {size, color, align, upright, halo})` draws math-italic
    STIX Two Text. Use `_` and `^` for sub/superscripts: `"s_j"`, `"h^{(t)}"`,
    `"I^†_h"`, `"⟨φ(x), ψ(y)⟩"`, `"1/I(ε)"`. Defaults: size 60, colour `C.ink2`,
    centred on (x, y). `halo: true` puts a `C.bg` plate behind the label.
  - `check(x, y, s, color, weight)` and `cross(x, y, s, color, weight)` draw ✓/✗ marks
    (never use font glyphs for these).
- **Sparse:** about 5 labels or marks per image at most. Each one names an
  element (x, z, R, π¹, I†); none is a sentence. A short word is allowed only
  when essential.
- **Size ≥ 56 px** (about 10 px at 220×140). Use `C.ink2` by default, `C.ink`
  for the single most important label, `C.accent` only when labelling the accent element.
- The image must still read at 96×72, where labels are illegible: they are an
  aid, not load-bearing.
- Keep labels out of the tag keep-out (x < 360, y > 640) and inside the
  crop-safe band. Place them in clear space next to what they name, not on top
  of lines (use `halo` if a crossing can't be avoided).

## Round 3 additions: second accent, arrows, words

- **`C.accent2` / `C.accent2Soft`** (red by default). Use these only when a
  paper's idea is *two kinds of thing* that must be told apart, e.g. sensory
  (red) vs relational (blue, `C.accent`). The budget stays the same, and it is
  shared: both accents together cover ≤ 12% of the area.
- **`C.cat`** is a five-colour categorical set (accent, red, green, amber, violet). Use it
  only when the idea *is* several distinct categories that must be told apart,
  e.g. one colour per latent strategy z. Use it at stroke weight, not as big fills.
- **Arrows** are now allowed where direction matters (who sends to whom, edge
  direction in a DAG). Use only the helpers, so arrows look the same everywhere:
  `arrow(x1, y1, x2, y2, {color, weight, size})` for a straight arrow, and
  `arrowHead(x, y, angle, {color, size})` at the end of a curved path. Heads
  are 22–34 px. Use them sparingly.
- **Words:** when the user asks for one, a short word label (e.g. "sensory",
  "Environment") is fine. Draw it with `label(..., {upright: true})` so words
  are upright and math stays italic.

## Animation (optional, conservative)

Only animate when motion makes the concept clearer (drift vs. snap, best-reply
hops, grains falling through a neck), never as decoration.

- Declare `anim: { duration: 4, fps: 20, stillPhase: 0 }` (3–6 s loop, ≤ 20 fps).
- `draw` is then called once per frame with `t ∈ [0, 1)` (loop phase) and
  `still` (boolean). Each call starts from a fresh background and the same seed,
  so `p.random()` returns identical values on every frame. Animate only through
  `t`. **The loop must be seamless:** the frame at t = 1 equals the frame at t = 0.
- **Every animated option also ships a static image.** That is the call with
  `still: true` (at phase `stillPhase`). It must be a complete, standalone
  composition, e.g. showing whole trajectories rather than a dot mid-flight.
  Branch on `still` if the static version needs extra marks.
- Keep the moving parts small and the rest static. That keeps the WebP small
  (target ≤ 400 KB at 800×600) and the tile calm.
- Output: `renders/<base>.{paper,ink}.png` (the stills) and
  `renders/anim/<base>.paper.webp` (the loop).

## Composition (must read at 96×72)

- **One focal structure** whose bounding box covers at least 70% of the width
  and at least 65% of the height. The thumbnail should read as one confident
  silhouette plus an accent mark, never as a small object in a big empty tile.
- Outer margin of about 90 px (7.5%) for focal content; texture and lines may
  bleed off the edges.
- **Crop-safe band:** on narrow screens the tile is shown at 220×140, which
  crops about 70 px from the top and bottom. Keep anything essential within
  y ∈ [110, 790].
- **Tag keep-out:** a small "ML" badge overlays the bottom-left of the
  thumbnail. Keep focal elements out of x < 360, y > 640 (texture there is fine).
- Density: at most ~150 primary elements. Large families (dozens of paths, a
  lattice of hundreds of dots) must use `faint`/`ink2` and thin weights so they
  become tone.
- Balance comes from the algorithm, not from decoration: symmetry, a lens, a
  fan, a lattice, an arc dome, or a braid.

## Sketch contract

One file per option. Round 1 used `sketches/<slug>-<A|B|C|D|E>.js`. Round 2
uses the proposal ids: `sketches/<slug>-<P1|P2|…|R1>.js`.

```js
// <Paper short name> · option P1 · "<Title>"
// 2–4 lines: which concept this depicts and how the algorithm encodes it.
PreviewArt.register({
  slug: "<slug>",
  option: "P1",
  round: 2,
  title: "<2–4 word title>",
  concept: "<one sentence: which key concept this depicts>",
  legend: "<element → meaning; element → meaning; …>",   // shown in the gallery
  seed: 7,                          // the chosen seed
  params: { /* meaningful knobs, in the paper's terms */ },
  // anim: { duration: 4, fps: 20, stillPhase: 0 },   // only if animated
  draw(p, C, { W, H, seed, params: P, t, still, label, check, cross }) {
    // p is a p5 instance (instance mode: p.circle, p.random, p.noise, ...).
    // The canvas is already filled with C.bg and seeded (randomSeed and noiseSeed).
    // Use only p.random/p.randomGaussian/p.noise. Never use Math.random().
  },
});
```

Render and check:

```
node lib/render.mjs sketches/<slug>-*.js          # renders/<file>.{paper,ink}.png
node lib/sheet.mjs renders/sheet-<slug>.png renders/<slug>-{A,B,C}.paper.png
```

The sheet shows each option at 600×450 alongside its real 96×72 thumbnail and a
2× zoom of that thumbnail. Read the sheet image, judge the thumbnails
honestly, and iterate: try seeds, tune weights, and fill the frame.
Check the `.ink.png` (dark) renders too.

## Checklist per option

1. Does it depict a specific concept from *this* paper, one that its authors would recognise?
2. At 96×72: is there one clear silhouette, and is the accent visible?
3. Does it work in both the light (`paper`) and dark (`ink`) palettes?
4. Does it use only the six tokens, with no gradients or Math.random? Are the
   labels sparse, drawn with the helpers, ≥ 56 px, and is each next to what it names?
5. Is it within the crop-safe band and clear of the tag keep-out?
6. Do the options within one paper differ in concept or structure, not just seed?
7. Can a reader name what every element stands for, using the labels and the `legend`?
8. If animated: is the loop seamless, is the motion small and meaningful, and
   does the still stand on its own?
